# Footwear monthly revenue monitor (proposed)

PR deployment status: **not active until merged into main**.

Tracks 9802, 6768, 9910, 9904, 6890, 6965, 9938 and 8404. Workflow `.github/workflows/shoe_revenue_monitor.yml` runs twice per day and supports manual dispatch with a YYYY-MM month. It fetches TWSE/TPEx official open-data endpoints and stores an observation snapshot at `tw-market-data/revenue/shoe_revenue_latest.json`.

## Evidence and safeguards
- Month must be explicitly present in the official row; missing, malformed, or mismatched months are skipped.
- Official feed failures fail the run and preserve the previous snapshot.
- Missing issuers are reported in `missing_codes`; they are **not zero-revenue issuers**.
- Older manual runs cannot replace a newer snapshot.
- The output is **not MOPS filing certification** and contains no original-document SHA-256 receipts.
- No stock alerts or trading recommendations are generated by this workflow.
- It is a single latest-month snapshot, not a historical database.

## Validation required before enabling
1. Verify both official endpoint URLs, returned JSON field names and units against real responses for the requested month.
2. Run `python -m unittest discover -s tests -p 'test_shoe_revenue_monitor.py' -v` and review GitHub Actions job logs.
3. Confirm repository Actions has `contents: write` permission, and protect against competing pushes with other scheduled workflows.
4. Compare 9802 and other company figures with MOPS original filings before labeling them verified.
5. Add notifications and an immutable per-month archive in a separate reviewed change.
